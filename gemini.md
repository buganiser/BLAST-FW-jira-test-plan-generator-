---

## 2. Behavioral Rules

1. **IEEE 829 Compliance**: All test plans MUST follow IEEE 829 standard structure
2. **Jira-First**: Primary data source is the Jira ticket (SCRUM-10); no external templates
3. **Dual Delivery**: Output MUST be saved as Markdown file AND posted as Jira comment
4. **Deterministic Generation**: Same ticket input → same test plan output (idempotent)
5. **No Placeholder Content**: Every section must have meaningful content derived from ticket
6. **Traceability**: Each test item MUST reference source acceptance criteria
7. **Risk-Based**: Assign risk levels (High/Medium/Low) based on priority, complexity, business impact
8. **Audit Trail**: Log all API calls, generation steps, and delivery actions

---

## 3. Architectural Invariants

1. **Single Responsibility**: Separate modules for Jira fetch, test plan generation, file write, Jira comment
2. **Configuration over Code**: Jira credentials, endpoints, output paths in config file
3. **Error Handling**: Graceful degradation — if Jira comment fails, file still saved; log error
4. **Testability**: Core generation logic pure functions; I/O at boundaries only
5. **Extensibility**: Plugin architecture for different output formats (future-proof)
6. **Security**: No credentials in code; use environment variables or secure config
7. **Versioning**: Test plan version increments on re-generation
